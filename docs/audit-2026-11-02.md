# Audit Myspoti — chargement, lecture, interface, extensions, build (2 novembre 2026)

Base : `main` à `8e8898af` (2.3.0), branche `audit/deep-2026-11`. Téléphone : Galaxy S24 (SM-S921B, Android API 37), build debug `app.myspoti.dev`.

Méthode : 11 auditeurs en lecture seule (démarrage, lecture, réseau/cache, Compose Immersive, Compose classique, UI/UX, concurrence/mémoire, extensions, build/taille, outils/docs, imports open source), puis contre-vérification adverse. La vérification a été arrêtée en cours pour économiser le quota : **21 constats confirmés, 8 réfutés, 120 à vérifier** avant toute correction. Une ligne « à vérifier » est l'avis d'un seul auditeur, pas un fait établi.

## 1. Mesures de référence sur le téléphone

- Démarrage à froid (logcat `Displayed`, debug) : ~1,37 s ; `Choreographer: Skipped 96 frames` (~800 ms de thread principal bloqué) au démarrage. `am start -W` ne rend jamais `TotalTime` (LaunchState UNKNOWN).
- Démarrage à froid → la CLI dit `signedIn` (horloge de l'hôte) : 1,77 à 1,81 s.
- Moteur Spotify (`tools/tap_latency.py`, n=5) : tap sur un titre médiane **1 625 ms** (882–2 647) ; suivant 609 ms ; précédent 391 ms ; reprise 112 ms.
- Chemin extension (Tidal, lecteur local), `next` → nouveau titre joué (hôte, polling CLI compris) : médiane ~1,9 s. Vu une fois : l'extension `lossless` a mis **11,9 s** à rendre un flux (timeout Deezer), la lecture a attendu tout ce temps.
- Écran lecteur 12 s (`qa.py --perf`, debug) : 183 images, 16 en retard ; CPU app 130 %, rendu 104 %.
- `playback_test.py` (extensions coupées, autres builds Myspoti arrêtées) : 18/19.

## 2. Corrigé dans cette branche

- **Pub audible après un choix de titre** (scénario `ad_pick`, audible 2 fois sur 2 avant, 0 sur 4 passes après ; `ad_taps`, `ad_previous`, `ad_pick` : 16/16). `media.mute` baissait le volume une seule fois ; la page le remontait (nouveau titre, sa montée de volume, un volume Spotify Connect) et la pub s'entendait jusqu'au passage suivant, ~2 s plus tard. Un garde sur `volumechange`/`playing` tient chaque élément silencieux tant que la pub est coupée ou la page « hushed », posé dès le premier `play()` par le hook de début de document (`ControlRelay.kt`) et repris par le pont (`player-bridge.js`), qui remplace l'ancien garde propre à `media.hush`.
- **`playback_test.py` lit le log de la seule app testée** (`logcat --uid`) : une autre build Myspoti installée (`app.myspoti.automix2`, page gelée en arrière-plan) écrit sous les mêmes tags et faisait échouer 14 scénarios sur 19 avec ses propres timeouts.
- **`myspoti-cli`** trouve l'adb du SDK (`~/android-sdk/platform-tools/adb`) quand aucun n'est dans le PATH, comme `cdp.py`.
